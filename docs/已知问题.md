# 已知问题

按时间倒序，修掉的从这上面删掉。

## 还没有性能基线

现在只能证明能起服、能登录、日志干净。Leaf + Gale 到底比原版 Purpur 快多少，没有数字。要上生产，得拿原版 Purpur 用同一张图、同样在线人数各跑 30 分钟，采 TPS/MSPT 对比。

## 上游更新不会自动打包

仓库里没有 CI。之前有个 `build.yml`，2 核 7G 的机器编不动 paperweight 全量，七次全红，删了。Paper / Purpur / Leaf / Gale 发新版之后，得有人手动拉代码、重放补丁、重编。

## 字节级复现要本机 Paper 镜像

`gradle.properties` 里的上游提交指向本机 `G:\服务端\.paper-local.git`，这个裸仓库没进 Git。换机器重建之前，编出来的 jar 和内层 patch 不会跟发布包一模一样（功能一样，字节不同）。

## 首次启动必须联网

这个 jar 是 paperclip 结构，里面只有 22MB 的 server patch，原版 `mojang_26.3.jar` 和依赖库要现场下。纯内网部署得把跑过一次的 `cache/`、`libraries/`、`versions/` 一起拷过去。

## Gale 只剩 44 条

158 条 per-file 补丁里有 114 条没进（70 条记录在 `fhm-toolchain/gale-exclude.txt`），原因多数是跟 Leaf 或 Purpur 改到同一段代码。想再合并，得逐条对照重写，不是简单打补丁能解决的。

## flat 测试世界会报一条 `No key layers`

只在 `level-type=minecraft\:flat` 的冒烟环境里出现，正常世界不出。属于测试配置的噪音。
