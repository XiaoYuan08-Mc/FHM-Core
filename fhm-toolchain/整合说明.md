## Gale 这轮怎么做的

1. 补丁源：Gale `dev/26.3` 的 158 条 per-file 补丁（`gale-server/minecraft-patches/sources`），先把非标准 hunk 头 `@@ -a,b +_,c @@` 规范成标准格式（`fix-patch-headers.ps1`）。
2. 落地方式：`patch -p1 -F0`（严格上下文）。只要出现模糊匹配或 hunk 失败就 `git reset --hard` 丢弃该补丁，绝不让错位插入污染源码。得到 **44 条**，逐条一个 `gale: <Name>` 提交，基线为 Leaf 整合后的 `a49027`。
3. 补的垫片：
   - `org.galemc.gale.async.SimulationFlag`（推测执行开关，恒 false）
   - `galemc` 的 `idawarevalue`、`util.array`、`util.collection.packed`、`util.collection.blockstate`、`util.function`、`registry.blockstate` 等自有类（只保留补丁真正引用的，删掉依赖 Paper 配置/命令框架的 `command`、`task`、`GaleConfigurations`）
   - `GaleGlobalConfiguration` 补齐 26.3 被裁空的配置字段（`gameplayMechanics`、`logToConsole.*`、`misc`、`smallOptimizations`），默认值保持原版行为
   - Leaf 的 `BlockMasks`
4. 修掉的真实冲突：
   - `TagKey.equals` 重复定义（保留 Paper/Leaf 那份，删 Gale 那份；`hashCode` 缓存保留）
   - `BlockStateIdMapper.byId` 无法覆盖已 `final` 的 `IdMapper.byId` → 移除该类与其 `Block.java` 补丁
   - `PoiTypes` 的 `BasicBlockState2ObjectMap` 按 `BlockState.indexInRegistry` 索引，在 Paper 的区块状态注册表上会撞索引，导致启动即 `Block{blast_furnace} is defined in more than one PoI type` → 换成原生 `HashMap` 包装，保留“写回 `BlockState.gale$precompute_poiType`”的预计算，重复检测回归原版

- 实体：`Animal` / `TamableAnimal` / `Ravager` / `ItemEntity` / `AbstractArrow` / `FireworkRocketEntity` / `FishingHook` / `ShulkerBullet`

## Gale 未纳入的 70 条（原因分类）

- 32 条 `event-driven` 系列：依赖 `Entity` / `Mob` 的基础设施补丁，而这俩文件已被 Leaf 深度改造，严格上下文打不进；硬合会把 `gale$eventDriven_*` 方法与其字段拆散
- 32 条 `BlockState` 谓词预计算系列：Gale 26.3 用的是新版 `BlockMasks` API（`RAILS_TAG`、`CAULDRONS_TAG` 等谓词掩码 + `BlockState.isAny(...)`），Leaf 侧可复用版本 API 不一致，需重写整套掩码
- 其余：`ChunkMap` / `ServerEntity`（`seenBy` 容器类型已与 Paper 分歧）、`ServerLevel` / `Level` / `MinecraftServer` / `Services`（Gale 配置装配）、`PlayerList`（`CraftPlayer.resetCanSee`）、`ServerClockManager` / `ClockInstance`（推测执行时钟 `rewind()`）——都是整组符号互相引用，缺一环整条失效

- `Holder.is(TagKey)` 位集在标签未绑定时会是 null（运行期新建 holder 会 NPE）→ 加 null 兜底，按“不在该标签”处理

- `TagKey.equals` 重复 → 保留 Paper 版，保住 Gale 的 `hashCode` 缓存
